# تعلم الإنجليزية معنا

نسخة أولية عملية لمنصة تعليم إنجليزية عربية RTL: بوابة للأستاذ والطالب، تسجيل دخول بأدوار، إدارة دورات ودروس، تفعيل/تجميد الطلاب، طلبات دفع يدوية عبر بنكك، وتنزيل ملفات محمي بصلاحيات الدورة.

## التشغيل المحلي

المتطلبات: Node.js 20.19 أو أحدث (متطلب Mongoose الحالي) وMongoDB محلي أو MongoDB Atlas. لا يوجد حساب سحابي أو مفتاح سري مضمّن في المستودع.

1. ثبّت الاعتماديات باستخدام `npm install`.
2. انسخ `.env.example` إلى `.env` وعيّن `MONGO_URI` و`TOKEN_SECRET` وكلمات المرور السرية.
3. أضف `GMAIL_USER` و`GMAIL_FROM` و`GMAIL_APP_PASSWORD` من إعدادات App Password في حساب Google مع تفعيل التحقق بخطوتين.
4. شغّل `npm start` وافتح `http://localhost:5000`.

شغّل فحص صياغة JavaScript عبر `npm test`. لم تُنفذ بعد اختبارات تكامل على MongoDB.

إذا عيّنت `SUPER_ADMIN_PASSWORD` في `.env`، يهيئ بدء الخادم تلقائياً الحساب `sameyasen04@gmail.com` بدور `super_admin` وحالة `active` ويحدّث hash كلمة مروره. ويمكن تشغيل العملية نفسها يدويًا عبر `npm run seed:super-admin`. يقبل بدء التشغيل `ADMIN_PASSWORD` كاسم متغير قديم بديل فقط عند غياب `SUPER_ADMIN_PASSWORD`، لكنه يهيئ الحساب بدور `super_admin` أيضًا. عند إغلاق بوابة الطلاب، يعيد تسجيل دخول الطالب HTTP 403. لا ترفع `.env` إلى Git. في الإنتاج استخدم HTTPS واضبط `NODE_ENV=production`.

لتهيئة حساب المدير العام الذي يملك بريد `sameyasen04@gmail.com`:

1. عيّن `SUPER_ADMIN_PASSWORD` محلياً في `.env` إلى كلمة مرور قوية، ولا تضعها في الشيفرة أو المستودع. لا تستخدم كلمة المرور القصيرة المذكورة في الطلب؛ اختر كلمة طويلة وفريدة.
2. نفّذ `npm run seed:super-admin`. ينشئ الأمر الحساب أو يحدّثه إلى `super_admin` و`active`، ويخزن bcrypt hash بكلفة 12؛ تكرار الأمر يغيّر كلمة المرور إلى القيمة الحالية في البيئة.
3. سجّل الدخول بالبريد وكلمة المرور المعيّنة؛ سيرسل النظام رمز OTP إلى البريد المسجل لإكمال الدخول.

المدير العام المرتبط بالبريد الأساسي وحده يستطيع إنشاء حسابات `teacher`. الأستاذ والمدير العام يستطيعان التحكم في فتح بوابة الطلاب. البوابة مغلقة افتراضياً، وإغلاقها يبطل دخول الطلاب الحالي والجديد؛ صلاحيات طاقم التدريس تبقى متاحة.

تسجيل الدخول يتحقق أولاً من البريد وكلمة المرور، ثم يرسل رمزاً من 6 أرقام إلى البريد المسجل. الرمز صالح 10 دقائق، له خمس محاولات كحد أقصى، ويخزن كـ HMAC hash ويُستهلك مرة واحدة. يمنع الخادم طلب رمز آخر لنفس البريد لمدة دقيقة. استخدم Gmail App Password لا كلمة مرور Gmail الأساسية، ولا تضع أسرار SMTP في الواجهة أو المستودع. حقل البريد فارغ عند الفتح مع تعطيل autocomplete ومثال عام فقط.

## المعمارية الحالية

- الواجهة: HTML/CSS/JavaScript خفيف بلا إطار عمل، RTL، وتعمل بتصميم متجاوب. لا تحتاج لتنزيل حزم أو خطوط وقت فتح الصفحة.
- التطبيق والخلفية: Express API وخادم ملفات ثابتة من عملية Node واحدة؛ التحقق من المدخلات والصلاحيات في الخادم.
- قاعدة البيانات: MongoDB/Mongoose. النماذج هي `User` (أدوار وحالة وتسجيل بالدورات)، `Course` (النشر والدروس والاختبارات وإجاباتها)، `Payment` (الوسيلة والمرجع والإيصال والمراجعة)، `Progress` (إنجاز الدرس)، `QuizAttempt` (الإجابات والنتيجة)، `Attendance` (دخول يومي فريد لكل طالب)، `Message` (مراسلات الأستاذ والطالب)، و`Asset` (بيانات الملف ومالكه).
- الجلسات: JWT داخل cookie من نوع HttpOnly وSameSite=Strict؛ صلاحية الجلسة 12 ساعة، ولا تصدر إلا بعد تحقق كلمة المرور ورمز البريد. بوابة الأستاذ تقبل `teacher` و`super_admin`، وبوابة الطلاب تقبل `student` فقط عند فتحها. إنشاء أساتذة جدد مقصور على `super_admin` بالبريد الأساسي؛ الأدوار القديمة `admin` لا تدخل أي بوابة حتى ترقيتها.
- المرفقات: PDF وصور وصوت بحد أقصى 5 MiB للملف، محفوظة محلياً في `private_uploads` وخارج المسار العام. وصول الملف يمر بفحص الملكية أو تسجيل الطالب في الدورة.

## استخدام المنصة

بوابة الأستاذ على `/teacher/login` وبوابة الطلاب على `/student/login`، مع تبويبين للتنقل في أعلى الصفحة. تعرض بوابة الطلاب تنبيه الإغلاق فقط عندما تكون مغلقة، بينما تبقى بوابة الأستاذ متاحة.

الأستاذ ينشئ دورة ويحدد نشرها، ثم يضيف درساً برابط HTTPS (يوصى بفيديو MP4 منخفض الدقة مستضاف مسبقاً) أو ملفاً صغيراً، وينشئ اختبارات اختيار من متعدد. من تبويب الطلاب ينشئ حساب الطالب ويختار دوراته، ويمكنه تجميد الحساب فوراً بما في ذلك الجلسات المفتوحة. الطالب يطلب دورة، يختار بنكك، ويدخل مرجع التحويل مع إمكانية إرفاق صورة/PDF. الطلب يبقى معلّقاً حتى يقبله الأستاذ؛ عند القبول تضاف الدورة لحساب الطالب. يمكن للطالب تسجيل اكتمال كل درس، حل الاختبارات، ومراسلة الأستاذ. يحتسب الحضور مرة في اليوم عند تسجيل الدخول.

## التشغيل للسوق السوداني

- **الدفع:** لا توجد واجهة Bankak عامة/موثقة مدمجة هنا. التدفق الحالي تأكيد يدوي: الطالب يدخل مرجع العملية ويرفق الإيصال اختيارياً، والأستاذ يطابقه مع إشعار التحويل قبل القبول. اعرض رقم الحساب واسم المستفيد ومبلغ الدورة وتعليمات عدم مشاركة الرقم السري داخل صفحة الدفع قبل الإطلاق، بعد تزويدها ببيانات الجهة المالكة والتحقق منها.
- **الاتصال المحدود:** أبق الفيديو خارج خادم Node وارفع نسخة 240p/360p وملف صوت أو PDF مرافقاً. استخدم MP4 H.264/AAC ومدة قصيرة، وحجم مستهدف صغير، وقدم رابط تنزيل مباشر يدعم الاستكمال عبر HTTP Range من مزود التخزين/CDN. صفحات التطبيق نفسها قليلة النقل.
- **العمل دون إنترنت:** الروابط المباشرة للملفات قابلة للتنزيل والحفظ اليدوي. لا تدّعي المنصة مزامنة تقدم Offline في هذه النسخة. المرحلة التالية: Service Worker للأصول الثابتة فقط، ثم تنزيل الدروس المصرح بها ومزامنة أحداث الإنجاز عند عودة الاتصال.
- **الاستضافة:** استخدم خادماً قريباً من المستخدمين أو CDN إقليمياً، HTTPS، نسخاً احتياطية مشفرة لقاعدة البيانات والملفات، ومراقبة مساحة التخزين. ملفات الرفع الحالية محلية لذلك تتطلب تخزيناً دائماً في الاستضافة.

## واجهات API

- `POST /api/auth/request-otp`, `POST /api/auth/verify-otp`, `POST /api/auth/logout`, `GET /api/auth/me`
- `GET /api/catalog`, `GET /api/courses`, `GET /api/courses/:courseId`
- `GET /api/portal/status`, `GET /api/admin/platform-settings`, `PATCH /api/admin/platform-settings` (teacher/super-admin)
- `POST /api/admin/teachers` (super-admin only)
- `POST /api/admin/students`, `GET /api/admin/students`, `PATCH /api/admin/students/:studentId/status`
- `POST /api/admin/courses`, `PUT /api/admin/courses/:courseId`, `POST /api/admin/courses/:courseId/lessons`
- `POST /api/admin/courses/:courseId/quizzes`, `POST /api/courses/:courseId/quizzes/:quizId/submit`
- `POST /api/payments`, `GET /api/admin/payments`, `PATCH /api/admin/payments/:paymentId`
- `GET /api/progress`, `GET /api/admin/progress`, `PUT /api/progress/:courseId/:lessonId`
- `GET /api/admin/attendance`, `GET /api/admin/quiz-attempts`, `GET /api/messages`, `POST /api/messages`, `PATCH /api/messages/:messageId`
- `POST /api/uploads`, `GET /api/files/:assetId`

## ما يلزم قبل الإنتاج

هذه نقطة انطلاق وليست اعتماداً إنتاجياً بعد. أضف تحديد معدل أوسع حسب IP لمحاولات كلمة المرور والرفع، سجل تدقيق لتجميد الحسابات ومراجعة التحويلات، اختبارات آلية للمسارات والصلاحيات، سياسة خصوصية وموافقة على معالجة الإيصالات، نسخاً احتياطية واستعادة مجرّبة، وتخزين كائنات خاص بروابط مؤقتة بدلاً من القرص المحلي عند التوسع. ينبغي مراجعة متطلبات حماية البيانات والضرائب/الدفع المحلية مع مختص داخل السودان قبل تحصيل الأموال.
